Generics

Generics move type checks from runtime to compile time, then erase most of the evidence before the program runs.

~50 minContract tester3 objectives5 subgoals
  • Declare a generic class or method and explain what the type parameter promises.
  • Use a bounded type parameter when the implementation calls a method on the element.
  • Distinguish compile-time type safety from runtime invariant checks.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. A type parameter is a contract

    Box says the box holds one T. The caller chooses T once, and every get and put is checked against it.

  2. Bounds unlock operations

    T extends Comparable lets the method call compareTo. Without the bound, T could be any type and the call would not compile.

  3. Wildcards describe flexibility

    ? extends Number reads numbers; ? super Integer writes integers. The direction follows the producer/consumer rule.

  4. Erasure removes the parameter

    At runtime, List<String> and List<Integer> are both List. You cannot overload on type arguments or create a generic array directly.

  5. Invariants still need checks

    The compiler cannot prove that a capacity is positive or that a list contains no nulls. Generic safety does not replace boundary validation.

Worked examplePick: the largest of three comparable values

The bound is the whole method. Remove it and the comparison stops compiling.

public static <T extends Comparable<T>> T largest(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}

String word = largest("pear", "apple");
Integer count = largest(12, 7);

  1. Declare the type parameter

    <T extends Comparable<T>> appears before the return type. It is visible to the parameter list and the body.

  2. Use the bound

    Because T is comparable to itself, a.compareTo(b) is legal.

  3. Infer at the call site

    The compiler sees two Strings and chooses T = String. No cast is needed on the result.

  4. Reuse with another type

    The same method works for Integer because Integer implements Comparable<Integer>.

  5. Check the boundary

    If nulls are not allowed, the method must reject them. Erasure does not insert that check.

Predict, then observe

Before you step: Why does largest(1, "two") fail to compile instead of throwing at runtime?

Type inference must choose one T. Integer and String have no common comparable type, so the compiler rejects the call before bytecode exists.
