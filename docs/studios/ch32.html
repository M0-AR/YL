SQL and JDBC

SQL describes the result you want; JDBC is the boundary where Java types and database types meet.

~55 minData pipeline3 objectives5 subgoals
  • Write a parameterized query and read its result set.
  • Explain why string concatenation creates SQL injection risk.
  • Manage connection, statement, and result-set resources in the right order.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. SQL is declarative

    You state the rows and columns you want. The database chooses an execution plan. Ordering is not guaranteed unless you write ORDER BY.

  2. Prepared statements separate code from data

    A placeholder receives a typed value. The driver sends it as data, so a quote in the value cannot change the query structure.

  3. A result set is a cursor

    next() advances one row and returns false at the end. Read columns by label or index while the cursor is on a row.

  4. Close in reverse order

    Result set, statement, connection. Try-with-resources closes them in reverse declaration order and preserves the original exception.

  5. Transactions define a unit

    Set auto-commit false, perform several statements, then commit or roll back. A half-applied transfer is worse than a failed one.

Worked exampleHonorRoll: filter, order, limit

The SQL clauses are applied in a defined logical order. The result is a table, even when it has one column.

String sql = "SELECT id, name, score FROM students "
    + "WHERE score >= ? ORDER BY score DESC LIMIT ?";
try (PreparedStatement query = connection.prepareStatement(sql)) {
    query.setInt(1, 80);
    query.setInt(2, 3);
    try (ResultSet rows = query.executeQuery()) {
        while (rows.next()) {
            System.out.println(rows.getInt("id") + " " + rows.getString("name"));
        }
    }
}

  1. Parameter placeholders

    The question marks are positions, not text substitutions. The driver binds typed values to them.

  2. Bind the threshold

    The first parameter is an int, so the database compares numbers, not strings.

  3. Bind the limit

    The second parameter limits rows after filtering and sorting.

  4. Execute and iterate

    The cursor starts before the first row. next moves to the first match and returns true.

  5. Read by label

    Labels are clearer than indexes and survive a column reorder. The driver converts SQL types to Java types.

Predict, then observe

Before you step: What changes if the query is built as "... WHERE name = '" + input + "'" and input is ' OR '1'='1?

The condition becomes always true and returns every row. The input changed the query structure; a prepared statement would treat it as one literal name.

PracticeRebuild the program

A Parsons problem: the lines are correct, but the order is not. Rearrange them until the program would compile and behave as described.
