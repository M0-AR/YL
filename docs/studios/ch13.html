Abstract Classes and Interfaces

An interface is a promise without a body; an abstract class is a partial implementation with a boundary.

~40 minContract tester3 objectives5 subgoals
  • Choose between an interface and an abstract class for a design.
  • Write a contract that every implementation can satisfy.
  • Explain why default methods preserve backward compatibility.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. An interface names capabilities

    A class can implement many interfaces. Use an interface when unrelated types can share a promise.

  2. An abstract class shares partial state

    It can hold fields and concrete methods while requiring subclasses to finish specific operations.

  3. Contracts belong at the boundary

    Preconditions, postconditions, and invariants should be documented on the interface so every implementation is judged by the same rules.

  4. Default methods add behavior without breaking clients

    An interface can supply a method body. Existing implementers inherit it instead of failing to compile.

  5. Program to the interface

    Callers that depend on the interface can accept any implementation, including test doubles.

Worked exampleShapeContract: one interface, two implementations

The interface promises a name, an area, and a perimeter. The tester does not care whether the shape is a circle or a square.

interface Shape {
    String name();
    double area();
    double perimeter();
}
class Square implements Shape {
    private final double side;
    Square(double side) { this.side = side; }
    public String name() { return "square"; }
    public double area() { return side * side; }
    public double perimeter() { return 4 * side; }
}

  1. Interface

    No fields and no constructor; just the three promises.

  2. Implementation

    The class supplies the state and every method body.

  3. Positive side

    A valid implementation should reject a nonpositive side or document the precondition.

  4. Area and perimeter

    Both must be positive for every valid shape.

  5. Polymorphic use

    A method accepting Shape works with Square and any future implementation.

Predict, then observe

Before you step: If a new Circle class is added, does the tester need to change?

No, as long as Circle implements the same interface contract. That is the point of programming to the interface.

PracticeRebuild the program

A Parsons problem: the lines are correct, but the order is not. Rearrange them until the program would compile and behave as described.
