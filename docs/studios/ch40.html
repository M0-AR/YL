2-4 Trees and B-Trees

A multiway tree keeps data balanced by allowing nodes to hold several keys and by splitting before a node overflows.

~55 minStructure viewer3 objectives5 subgoals
  • Describe the key and child counts of a 2-3-4 tree node.
  • Trace an insertion that splits a full node.
  • Explain why a high branching factor reduces disk reads.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. A 2-node has one key

    A 2-node has one key and two children. A 3-node has two keys and three children. A 4-node has three keys and four children.

  2. All leaves are at the same depth

    The tree grows only by splitting the root, so every leaf stays on one level. Height grows slowly and uniformly.

  3. Split before descending

    If a child is full, split it before entering. The middle key rises to the parent, and the two halves become separate nodes.

  4. Order is local to the node

    Keys inside a node are sorted, and each child holds a range between neighboring keys. Search compares within the node, then chooses a child.

  5. Branching factor fits the storage

    A B-tree node can hold many keys, matching a disk block. Fewer levels mean fewer I/O operations for a lookup.

Worked exampleSplit: 10, 20, 30 becomes a parent and two children

Inserting 40 into a full root forces a split. The middle key moves up, and the tree gains one level.

// root is a 4-node: [10, 20, 30]
// inserting 40 makes the node overflow
int middle = 20;
// left child: [10]
// right child: [30, 40]
// new root: [20]

  1. Full root

    The root holds three keys, the maximum for a 4-node.

  2. Detect overflow

    A fourth key would exceed the node capacity. The split happens before the new key is stored.

  3. Promote the middle

    20 rises to a new root. It separates the smaller and larger keys.

  4. Split the remainder

    10 stays left; 30 and 40 form the right node. All leaves remain at the same depth.

  5. Search after split

    Search compares with 20 at the root, then enters the left or right child. The height increased by one, not by one per insertion.

Predict, then observe

Before you step: How many children does a 4-node have before it splits?

Four. Three sorted keys create four ranges, so a full 4-node has four child references even when those children are null at a leaf.
