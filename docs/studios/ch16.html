JavaFX UI Controls and Multimedia

Controls are small state machines; a form is a layout of those machines plus one place that reads their values.

~50 minLayout lab3 objectives5 subgoals
  • Select controls that match the shape of the data being collected.
  • Lay out a form with labels, inputs, and actions without relying on absolute positions.
  • Read control values at submit time and explain why live listeners are a different design.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Controls expose properties, not strings

    A TextField has a text property. A CheckBox has selected. Read the typed property instead of parsing a rendered label.

  2. Choose by cardinality

    One line of text: TextField. One choice from a short list: ComboBox or radio buttons. Many choices: ListView. Boolean: CheckBox.

  3. Labels are instructions

    A visible label connected to its control tells every user what the field means. Placeholder text disappears and is not a label.

  4. Validation belongs at the boundary

    Convert and validate when the form is submitted. Keep the raw control value until the conversion succeeds.

  5. Media has a lifecycle

    A MediaPlayer can play, pause, and stop. Release it when the view closes; a player holds native resources.

Worked exampleProfileForm: three controls, one read

The form does not react on every keystroke. It reads all controls in one place when the user submits.

public class ProfileForm extends Application {
    @Override
    public void start(Stage stage) {
        TextField name = new TextField();
        CheckBox notify = new CheckBox("Email me");
        ComboBox<String> plan = new ComboBox<>();
        plan.getItems().addAll("Free", "Pro", "Team");
        plan.setValue("Free");
        Button save = new Button("Save");
        Label result = new Label();
        save.setOnAction(event -> {
            String message = name.getText().trim()
                + " / " + plan.getValue()
                + " / notify=" + notify.isSelected();
            result.setText(message);
        });
        GridPane grid = new GridPane();
        grid.setHgap(8);
        grid.setVgap(8);
        grid.addRow(0, new Label("Name"), name);
        grid.addRow(1, new Label("Plan"), plan);
        grid.add(notify, 0, 2, 2, 1);
        grid.addRow(3, save, result);
        stage.setScene(new Scene(grid, 380, 200));
        stage.show();
    }
}

  1. Create the controls

    Each control is created with its own type. The compiler now helps: plan.getValue() is a String, not an Object.

  2. Seed defaults

    A ComboBox with a selected value cannot return null on the first submit. Defaults are part of the form contract.

  3. Attach the action

    Save is the only handler. It reads the three controls together, which keeps the snapshot consistent.

  4. Normalize input

    trim() removes accidental surrounding spaces. Validation would happen next, before the value reaches storage.

  5. Lay out by role

    addRow keeps label and field aligned. The checkbox spans both columns because it has no separate visible label.

Predict, then observe

Before you step: What does plan.getValue() return if the ComboBox is cleared with getItems().clear()?

It can return null. A cleared selection is not the same as the default value, so submit code must handle null before using the string.

PracticeRebuild the program

A Parsons problem: the lines are correct, but the order is not. Rearrange them until the program would compile and behave as described.
