Recursion

Recursion solves a problem by delegating a smaller copy of the same problem, then combining the result on the way back.

~45 minExecution trace3 objectives5 subgoals
  • Write a recursive method with an explicit base case and a smaller argument.
  • Trace the call stack and the return values for a small input.
  • Explain why naive Fibonacci recursion repeats work and how to avoid it.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Base case stops the descent

    Every recursive method needs an input it can answer without calling itself. Without a base case the stack grows until it overflows.

  2. The recursive case must shrink

    factorial(n) calls factorial(n - 1). If the argument does not move toward the base case, the method never terminates.

  3. Work happens on the way back

    The multiplication in n * factorial(n - 1) waits until the inner call returns. The stack holds the pending work.

  4. Each frame has its own locals

    The n in one frame is a different variable from the n in the caller. That separation is what makes the trace readable.

  5. Overlap is the performance trap

    Naive Fibonacci recomputes the same inputs exponentially many times. Memoization or an iterative loop removes the repetition.

Worked exampleFactorialTrace: five frames, one product

Read the stack from bottom to top on the way down, then read the returned values from top to bottom.

public static int factorial(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * factorial(n - 1);
}

  1. Call with 4

    n is 4, so the base case does not fire. The method must evaluate 4 * factorial(3).

  2. Descend to 3

    A new frame holds n = 3. The caller's frame stays alive with a pending multiplication.

  3. Descend to 2 and 1

    Two more frames are created. At n = 1 the base case returns immediately.

  4. Unwind

    1 returns to the frame with 2, which returns 2; that returns to 3, which returns 6; that returns to 4.

  5. Final value

    The outermost call returns 24. The stack is empty and every pending multiplication has been applied.

Predict, then observe

Before you step: How many calls to factorial occur for factorial(4), including the first?

Five: 4, 3, 2, 1, and the base-case call at 1. The sequence is one call per integer from 4 down to 1.
