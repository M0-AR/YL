AVL Trees

An AVL tree pays a little on every update to keep height logarithmic on every search.

~55 minStructure viewer3 objectives5 subgoals
  • Compute the balance factor of a node from subtree heights.
  • Trace a single rotation and a double rotation.
  • Explain why AVL height is O(log n) even in the worst case.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Height is measured in edges

    A leaf has height 0; a null child has height -1. A node's height is one plus the larger child height.

  2. Balance factor is left minus right

    If the factor is -1, 0, or 1, the node is balanced. A factor of 2 or -2 marks the lowest unbalanced node after an insertion.

  3. A single rotation fixes an outside case

    Left-left or right-right imbalance is repaired by rotating the child up and the old root down.

  4. A double rotation fixes an inside case

    Left-right or right-left requires two rotations: first straighten the child, then rotate the root.

  5. Balance is maintained on the way back

    Insertion updates heights as the recursion unwinds. The first unbalanced node is repaired, and the tree above it remains valid.

Worked exampleRightRotate: 30 leans left, 20 rises

The rotation changes three references. It does not change the inorder sequence, which is the point.

Node rotateRight(Node y) {
    Node x = y.left;
    Node t2 = x.right;
    x.right = y;
    y.left = t2;
    updateHeight(y);
    updateHeight(x);
    return x;
}

  1. Unbalanced root

    30 has left child 20 and no right child. The balance factor is 1 - (-1) = 2.

  2. Name the child

    x is 20, the new subtree root. t2 is x.right, currently null.

  3. Rewire

    20's right becomes 30, and 30's left becomes the old right of 20. Order is preserved: everything in t2 is between 20 and 30.

  4. Refresh heights

    Update the old root first because it is now lower. Then update the new root.

  5. Return the new root

    The caller must attach the returned node. Forgetting the return leaves the old root in place.

Predict, then observe

Before you step: If 20 had a right child 25, where would 25 end up after the right rotation?

It becomes the left child of 30. The subtree order 20 < 25 < 30 is preserved.

PracticeRebuild the program

A Parsons problem: the lines are correct, but the order is not. Rearrange them until the program would compile and behave as described.
