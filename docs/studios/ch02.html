Elementary Programming

Operators have precedence, types have rules, and the order of evaluation is not a suggestion.

~35 minExpression lab3 objectives5 subgoals
  • Evaluate a mixed arithmetic expression using Java precedence.
  • Distinguish integer division from floating-point division.
  • Predict when concatenation changes an expression from arithmetic to text.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Multiplication binds tighter than addition

    2 + 3 * 4 is 14, not 20. Parentheses are the only way to override precedence.

  2. Same-type arithmetic returns that type

    Two ints produce an int. 7 / 2 is 3 because the fractional part is discarded, not rounded.

  3. A cast changes the operation

    (double) 7 / 2 promotes the left operand, so the division becomes floating point.

  4. The plus sign is overloaded

    With two numbers it adds. With a string on either side it concatenates and converts the other operand to text.

  5. Assignment is right-associative

    a = b = 5 stores 5 in b, then stores that value in a. The expression itself has a value.

Worked examplePrecedenceLedger: one expression, three traps

The program prints four values. Only one of them is the result of doing everything left to right.

public class PrecedenceLedger {
    public static void main(String[] args) {
        int a = 2 + 3 * 4;
        int b = (2 + 3) * 4;
        int c = 7 / 2;
        double d = (double) 7 / 2;
        System.out.println(a + " " + b + " " + c + " " + d);
    }
}

  1. Precedence

    3 * 4 runs first, so a is 14.

  2. Parentheses

    The parentheses force addition first, so b is 20.

  3. Integer division

    Both operands are int, so the result is 3 and the remainder is discarded.

  4. Cast

    The cast applies to 7 before the division, producing 3.5.

  5. Concatenation

    The first + sees a string, so every later number is converted to text.

Predict, then observe

Before you step: What would 1 + 2 + "A" print, and why is it different from "A" + 1 + 2?

The first prints 3A because the numeric additions happen before the string appears; the second prints A12 because concatenation starts immediately.
