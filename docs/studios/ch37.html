Servlets

A servlet is a singleton living inside a container; the container owns its lifecycle and calls it on many threads.

~50 minState machine3 objectives5 subgoals
  • Describe the servlet lifecycle from init through destroy.
  • Separate request-scoped data from instance fields.
  • Explain why servlet instance fields are shared across requests.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. The container owns the lifecycle

    The container creates one servlet instance, calls init once, dispatches requests, and calls destroy before removal.

  2. One instance, many threads

    Requests run concurrently on the same instance. Instance fields are shared state and need synchronization or removal.

  3. Request and response are per call

    The HttpServletRequest and response objects belong to one exchange. Store per-request data in request attributes, not fields.

  4. Sessions span requests

    A session is server-side state keyed by a cookie or URL token. It is shared by one user, not by all users.

  5. Forward versus redirect

    A forward stays server-side and preserves request attributes. A redirect asks the browser to make a new request and loses request scope.

Worked exampleGreetingServlet: one instance, one request

The name comes from the request, never from a field. A field would leak one user's value into another user's response.

public class GreetingServlet extends HttpServlet {
    public void init() {
        log("ready");
    }
    protected void doGet(HttpServletRequest request, HttpServletResponse response)
            throws IOException {
        String name = request.getParameter("name");
        response.setContentType("text/plain; charset=UTF-8");
        response.getWriter().println("Hello, " + name);
    }
    public void destroy() {
        log("stopped");
    }
}

  1. Container creates the instance

    There is normally one servlet object, not one per request.

  2. init runs once

    Use it for expensive setup. It is not called for every request.

  3. Service dispatches

    The container selects doGet based on the HTTP method and calls it on a request thread.

  4. Request data stays local

    name is a local variable, so two concurrent requests cannot overwrite each other.

  5. destroy runs once

    The container calls it before shutting the servlet down; release resources here.

Predict, then observe

Before you step: What goes wrong if name is stored in an instance field instead of a local variable?

Two simultaneous requests can interleave writes to the same field, so one user can receive another user's name. The field is shared across threads.
