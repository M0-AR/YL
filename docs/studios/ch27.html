Hashing

Hashing turns a key into a bucket index; collisions are normal, and the collision policy decides the real cost.

~50 minStructure viewer3 objectives5 subgoals
  • Compute a bucket index from a hash code and table length.
  • Trace separate chaining through a collision.
  • Explain how load factor and resizing affect lookup cost.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Hash, then compress

    A hash code is an int. The table index is usually Math.floorMod(hash, capacity), which handles negative hashes correctly.

  2. Collisions are expected

    Different keys can map to the same bucket. A hash table is correct only because it has a policy for that case.

  3. Chaining stores a list per bucket

    Each bucket holds the entries that hashed there. Lookup scans only that bucket, not the whole table.

  4. Load factor measures crowding

    Entries divided by buckets. As it rises, chains lengthen. A resize allocates a larger table and rehashes every entry.

  5. equals must match hashCode

    If two objects are equal, they must have the same hash code. Breaking that contract makes an entry impossible to find.

Worked exampleSevenBins: three keys, one chain

The modulus is small on purpose. The collision is the lesson, not an accident.

int capacity = 7;
int a = Math.floorMod(Integer.hashCode(12), capacity);
int b = Math.floorMod(Integer.hashCode(19), capacity);
int c = Math.floorMod(Integer.hashCode(26), capacity);
// insert all three, then search for 19

  1. Empty table

    Seven buckets, each with an empty chain. Capacity is a power-of-two alternative in many libraries, but modulus works for any size.

  2. Insert 12

    12 mod 7 is 5, so 12 is stored in bucket 5.

  3. Insert 19

    19 mod 7 is also 5. The bucket now holds a chain; this is a collision.

  4. Insert 26

    26 mod 7 is 5 again. The chain has three entries, and lookup in bucket 5 becomes a short linear scan.

  5. Search 19

    Compute the bucket, then compare keys in the chain. A good hash spreads keys; equal keys always share a bucket.

Predict, then observe

Before you step: If the capacity doubled to 14, where would 12, 19, and 26 go?

12 → 12, 19 → 5, and 26 → 12. The collision between 12 and 26 remains, while 19 separates from them.

PracticeRebuild the program

A Parsons problem: the lines are correct, but the order is not. Rearrange them until the program would compile and behave as described.
