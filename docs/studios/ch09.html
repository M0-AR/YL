Objects and Classes

A class defines a contract; an object is one running instance with its own state.

~40 minContract tester3 objectives5 subgoals
  • Write a constructor that establishes every invariant immediately.
  • Distinguish a reference from the object it points to.
  • State preconditions and postconditions for a mutating method.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. The constructor must leave a valid object

    After new returns, every field should satisfy the class invariant. A half-built object is a bug waiting to escape.

  2. Fields hold state; methods define behavior

    Fields describe what an object knows. Methods decide what it can do and which state changes are legal.

  3. A reference can be shared

    Two variables can point to the same object. Mutating through one reference is visible through the other.

  4. this names the current object

    this.balance disambiguates a field from a parameter with the same name.

  5. Preconditions are the caller's job

    If a method requires a nonnegative amount, the caller must supply one. The class can also check and throw to fail fast.

Worked exampleAccount: a constructor and a guarded withdrawal

The constructor creates a valid balance. withdraw promises the balance never goes negative.

public class Account {
    private int balance;

    public Account(int initial) {
        if (initial < 0) throw new IllegalArgumentException();
        this.balance = initial;
    }

    public void withdraw(int amount) {
        if (amount <= 0 || amount > balance) {
            throw new IllegalArgumentException();
        }
        balance -= amount;
    }

    public int getBalance() { return balance; }
}

  1. Private field

    Only the class can change balance directly.

  2. Precondition on construction

    A negative initial balance is rejected before the object exists.

  3. Postcondition

    After construction, balance == initial.

  4. Guard before mutation

    The withdrawal rejects nonpositive amounts and overdrafts before touching the field.

  5. Valid mutation

    The subtraction preserves the invariant balance >= 0.

Predict, then observe

Before you step: What happens if withdraw(120) is called on an account with 100?

The guard fails and throws IllegalArgumentException. The balance remains 100.
