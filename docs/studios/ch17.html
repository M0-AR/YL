Binary I/O

Text I/O stores characters; binary I/O stores typed values in a defined byte order, which is smaller and faster but unreadable without the format.

~45 minState machine3 objectives5 subgoals
  • Choose between text I/O and binary I/O for a given persistence task.
  • Trace how a typed value becomes bytes and how a reader reconstructs it.
  • Explain why the writer and reader must agree on order, type, and count.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. A stream is an ordered byte channel

    FileInputStream reads bytes; FileOutputStream writes bytes. Higher-level streams wrap them to add meaning.

  2. Data streams preserve Java types

    DataOutputStream.writeInt writes four bytes. DataInputStream.readInt reads four bytes and rebuilds the int.

  3. Order is the schema

    A binary file has no column names. If the writer writes id then score, the reader must read id then score. Mismatch produces plausible garbage.

  4. Buffer to reduce calls

    A BufferedInputStream or BufferedOutputStream groups small operations. Use try-with-resources so the outermost close flushes and releases the file.

  5. EOF is a signal, not a value

    readInt throws EOFException when no complete int remains. That exception is a normal way to end a read loop, not necessarily a bug.

Worked exampleScoreFile: write two ints, read them back

The file is eight bytes: two four-byte ints. The offset is the only cursor; there are no separators.

try (DataOutputStream out = new DataOutputStream(
        new BufferedOutputStream(new FileOutputStream("scores.bin")))) {
    out.writeInt(72);
    out.writeInt(85);
}
try (DataInputStream in = new DataInputStream(
        new BufferedInputStream(new FileInputStream("scores.bin")))) {
    int first = in.readInt();
    int second = in.readInt();
    System.out.println(first + "," + second);
}

  1. Open the chain

    The file stream moves bytes; the data stream adds the int format; the buffer reduces system calls. Close the outermost wrapper.

  2. Write the first int

    72 becomes four bytes in big-endian order by default for DataOutputStream.

  3. Write the second int

    The offset is now eight. The file contains no field names, only the two values in order.

  4. Read in the same order

    The first read consumes bytes 0–3 and returns 72. Reading an int first would reinterpret the byte pattern, not recover the label.

  5. Print the pair

    The reconstructed values match because writer and reader agreed on type and order.

Predict, then observe

Before you step: What happens if the reader calls readLong() first on this file?

It consumes eight bytes and builds one long from the two ints. The bytes are valid, but the meaning is wrong. The second read then hits end of file.

PracticeRebuild the program

A Parsons problem: the lines are correct, but the order is not. Rearrange them until the program would compile and behave as described.
