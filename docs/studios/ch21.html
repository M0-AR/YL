Sets and Maps

A set answers membership; a map answers lookup. Both buy speed by giving up positional order.

~45 minData pipeline3 objectives5 subgoals
  • Choose a set or map when the problem is membership or keyed lookup.
  • Use a map to accumulate frequencies in one pass.
  • Explain the trade-off between hash-based and sorted collections.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Sets remove duplicates

    Adding the same value twice leaves one element. A HashSet does this in expected O(1); a TreeSet keeps sorted order in O(log n).

  2. Maps store a value per key

    Map<K,V> is not a Collection. It has keySet, values, and entrySet views, each with its own iteration order.

  3. getOrDefault removes a branch

    counts.merge(word, 1, Integer::sum) expresses increment without an explicit null check.

  4. Keys need stable equality

    A hash-based map relies on equals and hashCode. A mutable key that changes after insertion can become unreachable.

  5. Sorted is a cost and a feature

    A TreeMap supports range and order queries that a HashMap cannot answer without sorting. Choose by the query, not by habit.

Worked exampleWordTally: one pass, one map

Every word is a key. The merge operation handles the first occurrence and every later occurrence with the same expression.

String[] words = {"stream", "file", "stream", "buffer"};
Map<String, Integer> counts = new HashMap<>();
for (String word : words) {
    counts.merge(word, 1, Integer::sum);
}
List<Map.Entry<String, Integer>> ranked =
    new ArrayList<>(counts.entrySet());
ranked.sort(Map.Entry.<String, Integer>comparingByValue().reversed());
System.out.println(ranked);

  1. Input array

    The array may contain duplicates. The map, not the array, will enforce uniqueness of keys.

  2. Empty map

    No entries yet. The key type is String and the value type is Integer.

  3. Merge each word

    First occurrence: store 1. Later occurrence: combine old value with 1 using sum.

  4. Copy entries

    The entry set is a view. Copying it into a list allows sorting without modifying the map.

  5. Sort by count

    The comparator orders by value descending. Ties keep an arbitrary order because HashMap has none.

Predict, then observe

Before you step: If the sort used comparingByKey() instead, which word would appear first?

buffer, because keys would be sorted lexicographically. The frequency would no longer decide the order.
