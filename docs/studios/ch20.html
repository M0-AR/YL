Lists, Stacks, Queues, and Priority Queues

The collection interface tells you which end is legal; the implementation tells you what that operation costs.

~50 minStructure viewer3 objectives5 subgoals
  • Match a problem to a collection interface by its access pattern.
  • Trace add, remove, and peek operations on a list, stack, and queue.
  • Explain why a priority queue orders by priority rather than insertion time.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Interfaces name the operations

    List supports indexed access. Deque supports both ends. Queue supports offer, poll, and peek. Choose the interface first.

  2. Stack is LIFO

    The most recently pushed item is the first popped. Undo history and depth-first search both rely on this order.

  3. Queue is FIFO

    The earliest offered item is the first polled. Breadth-first search and work queues rely on this order.

  4. Priority is not arrival time

    A PriorityQueue returns the smallest element according to its comparator, regardless of when it was inserted.

  5. Implementation changes cost

    Indexed access is O(1) in ArrayList and O(n) in LinkedList. Add at the front is O(n) in ArrayList and O(1) in LinkedList or ArrayDeque.

Worked exampleTaskLane: one deque, two policies

The same data supports a queue when you add at the tail and a stack when you add at the head.

Deque<String> lane = new ArrayDeque<>();
lane.addLast("compile");
lane.addLast("test");
lane.addFirst("urgent-fix");
String next = lane.removeFirst();
String tail = lane.peekLast();

  1. Empty lane

    ArrayDeque is chosen because both ends are used and null elements are forbidden.

  2. Append two tasks

    compile is first, test is last. This is the queue order.

  3. Push to the front

    urgent-fix becomes first. The deque now supports stack-like priority without a second structure.

  4. Remove the front

    removeFirst returns urgent-fix and throws if empty. pollFirst would return null instead.

  5. Inspect the tail

    peekLast returns test without removing it. The lane still holds compile and test.

Predict, then observe

Before you step: After the steps shown, what is the lane from front to back?

compile then test. urgent-fix was removed, and peeking does not change the structure.

PracticeRebuild the program

A Parsons problem: the lines are correct, but the order is not. Rearrange them until the program would compile and behave as described.
