Implementing Lists, Stacks, Queues, and Priority Queues

Using a collection teaches the interface; implementing one teaches the cost hidden behind it.

~55 minStructure viewer3 objectives5 subgoals
  • Implement a dynamic array with append, get, set, and remove.
  • Explain when growth and shifting dominate the cost of a list operation.
  • Build stack and queue behavior on top of a list without changing the public contract.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Capacity is not size

    The backing array may be larger than the number of stored elements. size counts real elements; capacity counts available slots.

  2. Growth copies

    When the array is full, allocate a larger one, copy the elements, and replace the reference. A doubling strategy makes append amortized O(1).

  3. Insert and remove shift

    Adding or removing in the middle moves every later element by one slot. That is O(n) even though reading by index is O(1).

  4. Nodes trade memory for flexibility

    A linked list stores a next reference per element. Adding at the head is O(1), but indexed access must walk the chain.

  5. Adapters preserve semantics

    A stack can wrap a list with push and pop mapped to addLast and removeLast. The adapter defines which operations clients may use.

Worked exampleGrowList: append until the array doubles

Watch the capacity jump. The four appends are not all the same cost: the fifth triggers a copy.

String[] data = new String[4];
int size = 0;
void add(String value) {
    if (size == data.length) {
        data = Arrays.copyOf(data, data.length * 2);
    }
    data[size++] = value;
}
add("A"); add("B"); add("C"); add("D"); add("E");

  1. Initial capacity

    Four slots exist and size is zero. The array is not the list; it is storage the list manages.

  2. Fill without copying

    A through D occupy indexes 0–3. Each append is O(1) and size becomes capacity.

  3. The array is full

    The next add sees size == data.length. Writing past the end would throw an exception.

  4. Double and copy

    A new eight-slot array is allocated and the four elements are copied. This single add is O(n).

  5. Append E

    The new slot at index 4 receives E. Future appends are cheap again until the array fills.

Predict, then observe

Before you step: Why is doubling preferred over growing by one slot on every append?

Growing by one copies on every append, so n appends cost O(n²). Doubling copies at 1, 2, 4, 8… giving O(n) total copying for n appends.
