Java 8 Features

A stream pipeline describes a transformation lazily, then executes it once when a terminal operation asks for a result.

~50 minData pipeline3 objectives5 subgoals
  • Build a stream pipeline with intermediate and terminal operations.
  • Explain why intermediate operations do not run until a terminal operation is called.
  • Use a lambda to pass behavior without creating a named class.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. A lambda is a function value

    x -> x * 2 is behavior that can be passed to a method. The target type supplies the parameter and return types.

  2. Intermediate operations are lazy

    filter, map, and sorted build a pipeline description. They do not process elements yet.

  3. The terminal operation drives the work

    collect, forEach, count, and reduce request a result. Without one, the pipeline does nothing.

  4. Streams do not mutate the source

    A stream reads from a source and produces a new result. The original collection remains unchanged unless you explicitly modify it.

  5. Optional models absence

    findFirst returns an Optional. Callers must decide what to do when no value exists instead of risking a null.

Worked exampleBookPipeline: filter, sort, limit

The chain reads like the question: recent books, longest first, top three. Nothing executes until toList.

List<Book> selected = books.stream()
    .filter(book -> book.year() >= 2014)
    .sorted(Comparator.comparingInt(Book::pages).reversed())
    .limit(3)
    .toList();

  1. Open the stream

    stream() creates a view over the list. The list is not copied.

  2. Describe the filter

    The predicate is stored. No book is tested yet because the pipeline is lazy.

  3. Describe the order

    The comparator records how to sort. Sorting cannot happen until elements flow through.

  4. Describe the limit

    The limit is another stage. It may allow short-circuiting if the stream is ordered and the source is sized.

  5. Terminal operation

    toList pulls elements through the pipeline and returns a new list. The source list is unchanged.

Predict, then observe

Before you step: What does the pipeline do if the toList() line is removed?

Nothing. The intermediate stages are lazy descriptions; without a terminal operation, no element is processed.

PracticeRebuild the program

A Parsons problem: the lines are correct, but the order is not. Rearrange them until the program would compile and behave as described.
