Single-Dimensional Arrays

An array is one object holding a fixed number of same-typed slots, addressed by an integer index.

~40 minStructure viewer3 objectives6 subgoals
  • Declare, allocate, and initialize an array without confusing the three steps.
  • Use a loop and the length field to visit every element exactly once.
  • Explain why an index equal to length is out of bounds.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Declaration is not allocation

    int[] scores; creates a reference variable. new int[5] creates the array object. The braces form {72, 85, 91, 64, 88} combine creation and initialization.

  2. Indexes start at zero

    The first slot is index 0 and the last is length - 1. For five scores the legal indexes are 0, 1, 2, 3, and 4.

  3. length is a field, not a method

    Use scores.length without parentheses. The value is fixed when the array object is created.

  4. Traversal is a contract

    A correct loop starts at 0, continues while i < scores.length, and processes scores[i]. Changing either boundary is an off-by-one bug.

  5. Linear search reports a position

    Scan until the target is found, then stop. If the loop ends without a match, return -1 because -1 is not a legal index.

  6. Elements are mutable

    scores[2] = 95; replaces the value in that slot. The array object stays the same; only its contents change.

Worked exampleArrayAudit: one pass, three facts

The loop reads every element once and accumulates a sum. The cast to double is what prevents integer division from truncating the average.

public class ArrayAudit {
    public static void main(String[] args) {
        int[] scores = {72, 85, 91, 64, 88};
        int sum = 0;
        for (int i = 0; i < scores.length; i++) {
            sum += scores[i];
        }
        double average = (double) sum / scores.length;
        System.out.printf("sum=%d average=%.1f%n", sum, average);
    }
}

  1. Create the array object

    Five integer slots exist and are initialized to the listed values. The variable scores refers to the object.

  2. Accumulator starts at zero

    Zero is the identity for addition. Starting anywhere else would bias every result.

  3. Visit each slot once

    The guard uses <, not <=. When i reaches 5 the loop stops before touching scores[5].

  4. Convert before dividing

    Integer division would produce 80 instead of 80.0. Casting the sum to double changes the operation.

  5. Format the report

    %d prints an integer, %.1f prints one decimal place, and %n is a portable newline.

Predict, then observe

Before you step: What would the average print if the cast to double were removed?

It would print 80.0 because 400 / 5 is exact. Change the sum to 401 and the truncated result becomes visible: 80.0 instead of 80.2.
