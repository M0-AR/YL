Weighted Graphs and Applications

Weights turn a graph from a map of connections into a map of costs, and the cheapest path is rarely the shortest in edges.

~55 minGraph lab3 objectives5 subgoals
  • Represent weighted edges and distinguish path cost from hop count.
  • Trace Dijkstra's relaxation step and explain why negative weights break it.
  • Compare a shortest-path tree with a minimum spanning tree.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Cost is additive

    A path's cost is the sum of its edge weights. A path with fewer edges can be more expensive than a longer, lighter route.

  2. Dijkstra grows a settled set

    Repeatedly remove the unsettled vertex with the smallest known distance. Its distance is final because every edge weight is non-negative.

  3. Relaxation improves a guess

    If dist[u] + w(u,v) < dist[v], replace the guess for v and record u as its predecessor.

  4. Negative edges break the proof

    A later negative edge could lower a distance after a vertex was settled. Use Bellman-Ford when negative weights are possible.

  5. Shortest path is not spanning tree

    Dijkstra minimizes cost from one source to every vertex. Prim minimizes the total weight of a tree connecting all vertices.

Worked exampleRouteCost: settle A, relax neighbors

The table of tentative distances is the algorithm. The drawing only makes the relaxation visible.

Map<String, Integer> dist = new HashMap<>();
dist.put(start, 0);
while (unsettled not empty) {
    String u = vertex with smallest dist;
    settle(u);
    for (Edge e : edgesFrom(u)) {
        int candidate = dist.get(u) + e.weight;
        if (candidate < dist.getOrDefault(e.to, INF)) {
            dist.put(e.to, candidate);
            parent.put(e.to, u);
        }
    }
}

  1. Initialize

    The source distance is 0; every other distance is infinity. No vertex is settled.

  2. Settle A

    A has the smallest tentative distance, 0. Relax its edges: B becomes 2 and D becomes 6.

  3. Settle B

    B is next at 2. The edge to C gives 2 + 3 = 5, improving C from infinity. The edge to D gives 7, which is worse than 6.

  4. Settle C and D

    C settles at 5, D at 6. The edge from C to E proposes 11; the edge from D to E proposes 10, so E is updated.

  5. Read the tree

    Following parent links from E gives E ← D ← A. The route cost is 10 even though the hop count is 2.

Predict, then observe

Before you step: A direct edge A→E has weight 50. Why is it not chosen while A→D→E costs 10?

Dijkstra minimizes total cost, not hop count. Relaxation keeps the cheaper 10 and ignores the direct 50.
