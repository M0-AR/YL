Sorting

Sorting is the art of maintaining an invariant while the data is still moving.

~45 minSorting lab3 objectives7 subgoals
  • Explain the invariant that each sorting algorithm protects.
  • Compare quadratic and linearithmic growth using recorded comparisons.
  • Choose a stable algorithm when equal keys must keep their original order.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. An invariant is a promise that stays true

    Bubble sort promises the largest remaining values are already at the end. Selection sort promises the prefix is final. Insertion sort promises the prefix is sorted but not necessarily final.

  2. Comparisons and swaps are different costs

    A comparison reads two values. A swap writes two slots. Algorithms with the same comparison count can have very different write costs.

  3. Bubble sort moves large values right

    Each pass compares adjacent pairs and swaps when they are out of order. After pass k, the last k values are final.

  4. Selection sort minimizes swaps

    Find the minimum of the unsorted suffix, then place it once. It always performs about n²/2 comparisons but at most n - 1 swaps.

  5. Insertion sort is excellent on nearly sorted data

    Shift only while the left neighbor is larger. On an already sorted array the inner loop never runs, so the pass is linear.

  6. Merge sort divides before it conquers

    Split until ranges have one element, then merge two sorted ranges by repeatedly taking the smaller front value. The merge step is linear in the combined range.

  7. Stability is a property, not a speed

    A stable sort preserves the relative order of equal keys. Merge sort is stable when the merge takes from the left range on ties; selection sort is not.

Worked exampleSortTrace: insertion sort with visible passes

The program prints the array after each insertion. The printed snapshots are the same states the playground shows.

import java.util.Arrays;

public class SortTrace {
    public static void main(String[] args) {
        int[] values = {42, 17, 93, 8, 61, 24};
        for (int i = 1; i < values.length; i++) {
            int key = values[i];
            int j = i - 1;
            while (j >= 0 && values[j] > key) {
                values[j + 1] = values[j];
                j--;
            }
            values[j + 1] = key;
            System.out.println(Arrays.toString(values));
        }
    }
}

  1. Start at the second element

    A single element is already sorted, so index 0 is the initial sorted prefix.

  2. Save the key

    The value at index i will be overwritten during shifting, so it must be stored first.

  3. Shift larger values right

    The loop stops at a smaller value or at the beginning. Both conditions are required to avoid reading index -1.

  4. Insert into the gap

    After the shifts, j + 1 is the first position whose left neighbor is not larger. That is where the key belongs.

  5. Print after every pass

    The prefix grows by one sorted element per outer iteration. The suffix is untouched but not yet sorted.

Predict, then observe

Before you step: How many shifts happen when the input is already sorted, such as {1, 2, 3, 4}?

Zero. The while condition is false immediately at every pass, so insertion sort runs in linear time on sorted input.
