Binary Search Trees

A binary search tree keeps the ordering rule local: everything left is smaller, everything right is larger.

~55 minStructure viewer3 objectives5 subgoals
  • Insert and search in a binary search tree while preserving the ordering rule.
  • Trace an inorder traversal and explain why it sorts the keys.
  • Describe how deletion handles a node with two children.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. The invariant is local

    For every node, all keys in the left subtree are smaller and all keys in the right subtree are larger. Checking one node is enough if the invariant held before.

  2. Search follows comparisons

    Compare at the root, then descend left or right. Each step removes one subtree, so search is O(height).

  3. Insert at a leaf

    Follow the same path as search until a null child appears, then attach a new leaf there. The shape depends on insertion order.

  4. Inorder is sorted

    Left subtree, node, right subtree. The invariant places every smaller key before the node and every larger key after it.

  5. Deletion has three cases

    A leaf is removed directly. A node with one child is replaced by that child. A node with two children is replaced by its inorder successor or predecessor.

Worked exampleIntTree: insert, search, print in order

The tree shape is a side effect of insertion order. The ordering rule, not the shape, is the invariant.

Node insert(Node root, int key) {
    if (root == null) return new Node(key);
    if (key < root.key) root.left = insert(root.left, key);
    else if (key > root.key) root.right = insert(root.right, key);
    return root;
}

boolean contains(Node root, int key) {
    if (root == null) return false;
    if (key == root.key) return true;
    return key < root.key
        ? contains(root.left, key)
        : contains(root.right, key);
}

  1. Insert 50

    The empty tree becomes a single root. Its left and right children are null.

  2. Insert 30

    30 is smaller than 50, so it becomes the left child. The root does not move.

  3. Insert 70

    70 is larger than 50, so it becomes the right child.

  4. Insert 20 and 40

    Both compare against 50 then 30. 20 goes left of 30; 40 goes right of 30.

  5. Search 40

    40 < 50 so go left; 40 > 30 so go right; equal, found. The path length is the number of comparisons.

Predict, then observe

Before you step: What does an inorder traversal of the final tree print?

20, 30, 40, 50, 70. Inorder visits the left subtree, then the node, then the right subtree, which is ascending order for a valid BST.
