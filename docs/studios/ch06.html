Methods

A method is a named contract: parameters go in, a return value comes out, and the caller's state is isolated.

~35 minExecution trace3 objectives5 subgoals
  • Trace a method call through the call stack.
  • Explain pass-by-value for primitives and references.
  • Choose a return type and signature that make misuse hard.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. A call creates a new frame

    Parameters and local variables live in the callee's frame. The caller's variables are not the same storage even when the names match.

  2. Arguments are evaluated before the call

    max(7, 3) passes the values 7 and 3. The method receives copies, not the caller's variables.

  3. return ends the method and produces a value

    A non-void method must return on every reachable path. The returned value becomes the value of the call expression.

  4. Scope is where a name is visible

    A local declared inside a block disappears at the closing brace. Two methods can use the same local name without collision.

  5. Signatures are part of the API

    The name plus parameter types identifies a method. A clear signature makes the contract readable before the body is opened.

Worked exampleMethodTrace: one call, two frames

The call stack shows main paused while max runs. The result then returns to the caller.

public class MethodTrace {
    static int max(int a, int b) {
        return a > b ? a : b;
    }
    public static void main(String[] args) {
        int result = max(7, 3);
        System.out.println(result);
    }
}

  1. main starts

    No locals yet. The JVM calls main with an empty argument array.

  2. Evaluate arguments

    The literals 7 and 3 are ready. A new frame for max is created.

  3. max executes

    Inside max, a is 7 and b is 3. The conditional expression yields 7.

  4. Return

    The frame disappears and the value 7 replaces the call expression in main.

  5. Print

    result is 7, so the output is 7.

Predict, then observe

Before you step: If max assigned a = 0 before returning, would the caller's variable change?

No. The parameter is a copy in the callee's frame; the caller's variable is unaffected.
