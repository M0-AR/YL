Thinking in Objects

Encapsulation is not secrecy for its own sake; it is a small surface that can keep its promises.

~35 minContract tester3 objectives5 subgoals
  • Design a class boundary that protects an invariant.
  • Explain why returning a mutable field breaks encapsulation.
  • Choose composition when one object owns another.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Keep fields private by default

    A private field can only change through class methods, which is where the invariant checks live.

  2. Getters should not leak mutable internals

    Returning an internal array lets a caller change the object without passing through any guard.

  3. Composition means has-a

    An Invoice has a Customer. The contained object keeps its own identity and invariants.

  4. Copy on the boundary

    If a caller must receive internal data, return a copy. If a caller supplies data, copy it on the way in when ownership matters.

  5. Invariants are never optional

    Every public method is an opportunity to break an invariant. Either prevent the change or reject it before applying it.

Worked exampleScoreBoard: a private array with a safe view

The class owns its array. Callers can read a copy, but they cannot mutate the internal storage accidentally.

import java.util.Arrays;

public class ScoreBoard {
    private final int[] scores;

    public ScoreBoard(int[] scores) {
        this.scores = scores.clone();
    }

    public int[] snapshot() {
        return scores.clone();
    }

    public int total() {
        int sum = 0;
        for (int score : scores) sum += score;
        return sum;
    }
}

  1. Final field

    The reference cannot be reassigned after construction; the array contents still can change internally.

  2. Defensive copy in

    The caller's array is cloned, so later changes to it do not affect the board.

  3. Defensive copy out

    The snapshot is also a clone, so callers cannot mutate the internal array.

  4. Behavior on the inside

    The total is computed from the owned data, not from a caller-supplied array.

Predict, then observe

Before you step: If the constructor stored the caller's array directly, what could a caller do after construction?

It could change any score by writing to its own array reference, silently breaking the board's total.
