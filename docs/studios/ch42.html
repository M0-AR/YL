Testing Using JUnit

A test is an executable claim: arrange the state, perform one action, assert the observable result.

~45 minExecution trace3 objectives5 subgoals
  • Structure a JUnit test with arrange, act, and assert phases.
  • Choose assertions that fail with useful messages.
  • Explain why a test should exercise behavior rather than private implementation.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. One behavior per test

    A test that checks five unrelated facts hides which one failed. Name the test after the behavior and assert the smallest observable outcome.

  2. Arrange, act, assert

    Build the object, call the method once, then compare the result. Setup noise makes the action hard to see.

  3. Assertions carry the contract

    assertEquals compares values; assertThrows checks the exception type. The assertion should state what the caller observes.

  4. Tests must be independent

    A test should not depend on execution order or shared mutable state. Each test creates what it needs.

  5. Regression tests pin a bug

    A test written after a bug reproduces the failure before the fix and passes after it. That is the test's value.

Worked exampleCalculatorTest: one sum, one assertion

The test is short because the behavior is small. A failure points at one method and one expectation.

@Test
void addsTwoNumbers() {
    Calculator calculator = new Calculator();
    int result = calculator.add(2, 3);
    assertEquals(5, result);
}

  1. Annotation

    @Test tells JUnit to run the method as an independent test case.

  2. Arrange

    The calculator is created inside the test, so no other test can change it.

  3. Act

    One call performs the behavior under test. The result is stored, not printed.

  4. Assert

    The expected value is compared with the actual value. JUnit reports both on failure.

  5. Isolation

    No static state is touched, so the test can run in any order and in parallel.

Predict, then observe

Before you step: A test passes when run alone but fails in the full suite. What kind of defect does that suggest?

Shared mutable state or order dependence. One test is changing something another test assumes, which violates independence.

PracticeRebuild the program

A Parsons problem: the lines are correct, but the order is not. Rearrange them until the program would compile and behave as described.
