Exception Handling and Text I/O

An exception is a control path with a destination; catch only what you can actually handle.

~40 minState machine3 objectives5 subgoals
  • Trace a thrown exception from the failure point to the matching catch block.
  • Distinguish checked from unchecked exceptions.
  • Use try-with-resources to guarantee cleanup.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Throw unwinds the stack

    The JVM abandons the current frame and looks for a matching catch in each caller. Frames without a handler disappear.

  2. Catch by type

    A catch for a superclass accepts subclasses. Order specific catches before general ones or the general one shadows them.

  3. Checked exceptions are part of the signature

    The compiler requires callers to catch or declare them. Unchecked exceptions usually indicate programming errors.

  4. finally always runs

    Use it for cleanup that must happen whether the try succeeds, throws, or returns early.

  5. Fail with context

    Wrap a low-level exception in a domain exception when the caller needs to know what operation failed, not just which library threw.

Worked exampleParseGuard: recover from bad text

The first parse succeeds; the second throws, is caught, and the program continues with a fallback value.

public class ParseGuard {
    static int parse(String text, int fallback) {
        try {
            return Integer.parseInt(text);
        } catch (NumberFormatException ex) {
            return fallback;
        }
    }
    public static void main(String[] args) {
        System.out.println(parse("42", -1));
        System.out.println(parse("4o", -1));
    }
}

  1. Valid parse

    "42" becomes 42 and the method returns normally.

  2. Invalid parse

    "4o" cannot be converted. parseInt throws a NumberFormatException.

  3. Matching catch

    The catch in parse handles the exception, so the caller never sees it.

  4. Recovery

    The fallback -1 is returned instead of crashing the program.

Predict, then observe

Before you step: What would happen if the catch block were removed?

The exception would propagate out of parse. Because it is unchecked, the program would terminate with a stack trace unless a caller caught it.

PracticeRebuild the program

A Parsons problem: the lines are correct, but the order is not. Rearrange them until the program would compile and behave as described.
