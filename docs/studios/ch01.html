Introduction to Java

Write once, run anywhere starts with a clear boundary: source code, bytecode, and the JVM.

~30 minState machine3 objectives5 subgoals
  • Trace a tiny Java program from source text to screen output.
  • Explain what main, a statement, and a string concatenation each contribute.
  • Predict the value of a variable after reassignment without running the program.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Source is text; bytecode is the contract

    javac translates source into class files. The JVM reads those class files, so the same bytecode can run on another operating system with a compatible JVM.

  2. Every application starts at main

    public static void main(String[] args) is the entry point the JVM looks for. static means the method belongs to the class, not to an object.

  3. A variable is a named box with a type

    int lives = 3; reserves an integer slot, names it lives, and stores 3. The type decides which operations are legal.

  4. Assignment replaces, it does not compare

    lives = lives - 1; evaluates the right side first, then stores the result in the same box. The old value is gone.

  5. println converts values to text

    The + operator joins a string with another value. Java converts the number to text as part of the concatenation.

Worked exampleHelloBlueprint: three statements, one observable state

This program is deliberately small. Watch the variable, not just the output: the screen only changes on the last line.

public class HelloBlueprint {
    public static void main(String[] args) {
        int lives = 3;
        lives = lives - 1;
        System.out.println("Lives: " + lives);
    }
}

  1. Class shell

    The class name must match the file name. This is a compile-time rule, not a runtime one.

  2. Entry point

    The JVM calls main with an array of command-line arguments. An empty array is still an array.

  3. First assignment

    The box lives now holds 3. Nothing has been printed yet.

  4. Reassignment

    The right side reads 3, subtracts 1, and stores 2. The previous value is replaced.

  5. Output

    String concatenation turns 2 into text, so the console receives exactly Lives: 2.

Predict, then observe

Before you step: If the two assignment lines were swapped, what would the program print?

It would not compile: lives would be read before it is declared. Declaration order matters in Java.

PracticeRebuild the program

A Parsons problem: the lines are correct, but the order is not. Rearrange them until the program would compile and behave as described.
