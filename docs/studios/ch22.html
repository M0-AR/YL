Developing Efficient Algorithms

Efficiency is a claim about growth, not a stopwatch reading: how does the work increase when the input doubles?

~50 minGrowth chart3 objectives5 subgoals
  • Classify a simple loop or search by its asymptotic growth.
  • Explain why binary search requires sorted input and halves the range.
  • Separate algorithmic growth from constant-factor tuning.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Count the dominant operation

    A single loop over n elements is O(n). A loop inside a loop over the same n is O(n²). Constants and smaller terms are dropped.

  2. Halving gives a logarithm

    Binary search removes half the remaining range each step, so the number of steps is about log₂ n.

  3. Preconditions are part of the algorithm

    Binary search is only correct on sorted data. The sort may cost O(n log n), which can dominate a single search.

  4. Worst case is the promise

    Big-O usually describes an upper bound on the worst case. Two algorithms with the same bound can still differ by a large constant.

  5. Measure to confirm, not to define

    A benchmark on one machine cannot replace a growth argument. Use timing to detect constant factors and cache effects.

Worked exampleTwo searches, one sorted array

Linear search may get lucky early. Binary search keeps halving, so its worst case is far smaller.

public static int linear(int[] data, int target) {
    for (int i = 0; i < data.length; i++) {
        if (data[i] == target) return i;
    }
    return -1;
}

public static int binary(int[] data, int target) {
    int low = 0, high = data.length - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (data[mid] == target) return mid;
        if (data[mid] < target) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}

  1. Linear scan

    Every element is examined in the worst case. The loop is O(n).

  2. Sorted precondition

    Binary search assumes ascending order. Without it, the comparison at mid points the wrong way.

  3. Compute mid safely

    low + (high - low) / 2 avoids overflow that (low + high) / 2 can cause for very large indexes.

  4. Discard half

    One comparison eliminates half the range. After k steps the range is about n / 2^k.

  5. Stop on equality or empty range

    The loop ends when the target is found or low passes high. Either way the result is correct for sorted input.

Predict, then observe

Before you step: How many comparisons does binary search need, at most, for one million sorted elements?

About 20, because 2²⁰ is slightly more than one million. Linear search could need one million.
