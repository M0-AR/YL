Advanced JavaFX

Advanced JavaFX is mostly separation: the view declares structure, the model holds state, and controllers connect them without owning either.

~50 minLayout lab3 objectives5 subgoals
  • Separate an FXML view from its controller and model.
  • Bind a TableView to an observable list instead of rebuilding it by hand.
  • Choose between a dialog and an inline detail pane for an edit flow.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. FXML declares, Java behaves

    The FXML file names components and controller hooks. The controller handles events and exposes state; it should not hard-code the layout.

  2. Observable lists drive tables

    A TableView listens to an ObservableList. Adding to the list updates the table without a manual refresh call.

  3. Bindings remove synchronization code

    A bound property follows its source. If the label text is bound to the selected row, selection changes update the label automatically.

  4. Menus are commands, not state

    A menu item should invoke the same command as a toolbar button. Duplicating logic in each control creates two behaviors to maintain.

  5. Dialogs are a boundary

    A modal dialog blocks the owner window and returns a result. Inline editing keeps context visible. Choose by whether the user needs the rest of the screen.

Worked exampleBookTable: one list, three regions

The table, detail pane, and status bar all read the same selection. No region stores a second copy of the selected book.

public class BookController {
    @FXML private TableView<Book> table;
    @FXML private Label detail;
    private final ObservableList<Book> books = FXCollections.observableArrayList();

    @FXML
    private void initialize() {
        table.setItems(books);
        table.getSelectionModel().selectedItemProperty().addListener(
            (obs, oldBook, newBook) -> detail.setText(describe(newBook)));
    }
}

  1. Injected view parts

    The FXML loader assigns the table and label after constructing the controller. The fields are not created in Java.

  2. One observable source

    The list is the model for the table. Any code that adds a book mutates this list.

  3. Initialize after injection

    initialize runs when the FXML is fully loaded, so the injected fields are available.

  4. Listen to selection

    The listener receives old and new values. The detail label derives from the new selection.

  5. Handle null

    When the table is cleared, the new value can be null. describe must handle that or the UI throws.

Predict, then observe

Before you step: What happens if a book is added directly to a new ArrayList instead of the observable list?

The table never sees the change. It observes the list instance set with setItems, not every list that happens to contain books.

PracticeRebuild the program

A Parsons problem: the lines are correct, but the order is not. Rearrange them until the program would compile and behave as described.
