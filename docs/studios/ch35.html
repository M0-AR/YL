Advanced Database Programming

A database program is a transaction boundary: either every related change lands, or none of them does.

~50 minData pipeline3 objectives5 subgoals
  • Group related updates into one transaction with commit and rollback.
  • Use batch execution for repeated parameterized statements.
  • Explain why connection pooling changes the cost model of a server.

LessonSubgoals

Read the subgoals first. Each one is a small, checkable idea that the worked example and the playground will use.

  1. Auto-commit is a policy

    With auto-commit on, every statement is its own transaction. Turn it off when several statements must succeed together.

  2. Commit publishes, rollback discards

    Changes are invisible to other transactions until commit. Rollback returns the connection to its previous consistent state.

  3. Batches reduce round trips

    addBatch queues parameter sets and executeBatch sends them together. It changes latency, not transaction semantics.

  4. Metadata describes the result

    ResultSetMetaData reports column names and types. It is useful for generic tools, not for normal application queries.

  5. Pools reuse connections

    Opening a connection is expensive. A pool returns connections to a managed set; code must still close them so they return.

Worked exampleTransfer: debit and credit as one unit

The two updates are only meaningful together. The transaction is the unit of correctness.

connection.setAutoCommit(false);
try {
    debit.executeUpdate();
    credit.executeUpdate();
    connection.commit();
} catch (SQLException failure) {
    connection.rollback();
    throw failure;
} finally {
    connection.setAutoCommit(true);
}

  1. Start the unit

    Auto-commit is disabled. The next statements belong to one transaction.

  2. First update

    The debit changes rows inside the transaction. Other sessions do not see it yet.

  3. Second update

    The credit is applied in the same unit. If this fails, the debit must not survive.

  4. Commit

    Both changes become visible together and durable according to the database configuration.

  5. Failure path

    Rollback discards the partial work, and the exception is rethrown so the caller knows the transfer failed.

Predict, then observe

Before you step: What happens if the program crashes after the debit but before commit?

The transaction is rolled back by the database on connection loss. Neither the debit nor the credit is committed.

PracticeRebuild the program

A Parsons problem: the lines are correct, but the order is not. Rearrange them until the program would compile and behave as described.
